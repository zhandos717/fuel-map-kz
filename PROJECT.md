# Карта заправок Казахстана

**fuel-map-kz.web.app** — карта АЗС Астаны и Алматы, раскрашенная по жалобам и рекомендациям водителей из Threads.

Проект возник в августе 2026 года во время массовых жалоб на качество бензина. Отзывы существовали, но были размазаны по сотням комментариев — найти ответ на вопрос «можно ли заправиться вот здесь» было невозможно.

## Зачем

Люди спрашивали в комментариях, где заправляться, и каждый раз получали десяток противоречивых советов. Ответ существовал — он просто лежал разобранным на части по сотне веток, и собрать его руками перед каждой заправкой никто не станет.

Задача была не в том, чтобы сделать продукт, а в том, чтобы один простой вопрос перестал требовать часа чтения. За первый месяц картой воспользовались 16,9 тысячи раз.

Отсюда и все решения по методологии: цитаты с датами вместо выводов, обе стороны в каждой карточке, честный серый вместо выдуманного цвета. Карта полезна ровно настолько, насколько ей можно верить.

Дата документа: 30 сентября 2026.

## Как это сделано

Код, сбор данных и черновые вердикты — работа ИИ-агента (Claude Code). Роль автора — ставить задачи, проверять результат, решать спорные случаи и разговаривать с людьми в комментариях. Ни один цвет не попадает на карту без проверки человеком: агент предлагает вердикт с цитатами, решение за автором.

Такое разделение и есть главный принцип проекта. Пока правило окраски меняется, отдавать решение формуле или агенту целиком нельзя.

## Как устроено

### Стек

- **Фронт:** vanilla JS, Leaflet 1.9.4, тайлы OpenStreetMap. Без сборки, без зависимостей кроме Leaflet с CDN.
- **Данные:** Python-скрипты, запускаются вручную.
- **Хостинг:** Firebase Hosting, проект `fuel-map-kz`.
- **PWA:** манифест + service worker, работает офлайн.
- **Аналитика:** Cloudflare Web Analytics (без кук) и Google Analytics (G-5B4ZW2QSZL).

### Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Всё приложение: разметка, стили, логика, i18n, тексты справки |
| `stations.js` | `window.STATIONS` — массив точек: город, сеть, адрес, рейтинг 2ГИС, координаты, точность |
| `verdict.js` | `window.VERDICT` (по сетям) и `window.SPOT` (по адресам) — тексты на ru/kk/en |
| `places.json` | Исходник: 266 адресов из 2ГИС по городам и сетям |

| `fill_gaps.py` | Добор точек из OSM через Overpass API |

### Сборка данных

```bash
python3 geocode.py     # places.json + manual.json → stations.js
python3 fill_gaps.py   # добирает из OSM, склеивает дубли ближе 200 м
./deploy.sh            # выкладывает на прод
```

## Методология вердиктов

### Четыре цвета

| Цвет | Значение |
|---|---|
| 🟢 Зелёный | Советуют |
| 🔴 Красный | Жалуются |
| 🟠 Оранжевый | Мнения разошлись |
| ⚪️ Серый | В тредах не пишут |

### Приоритет правил

1. **Вердикт по конкретному адресу** — перебивает всё остальное. Разные точки одной сети ведут себя по-разному.
2. **Вердикт по сети** — для города или общий, если по городам не разделён.
3. **Рейтинг 2ГИС** — если отзывов о топливе нет вообще, но рейтинг ≥ 4.7 при ≥ 200 оценках, точка зеленеет. В карточке честно написано, что цвет получен из рейтинга, а там оценивают сервис и кофе, а не бензин.
4. **Иначе** — серый.

### Правила, выработанные по ходу

- **Цвет ставится по цитатам, а не по репутации сети.** Helios однажды стоял красным, хотя в его же карточке было написано «многие хвалят 95 Prime» — читатель это заметил, цвет пересмотрен.
- **Карточка всегда показывает обе стороны.** Если сеть красная, но кто-то ездит без проблем — это написано в том же тексте.
- **Недолив и обсчёт на кассе не влияют на цвет.** Это касса, а не топливо.
- **Живая жалоба перебивает высокий рейтинг 2ГИС.**
- **Формулировки:** «водители жалуются», а не «плохой бензин».

## Что выяснилось про данные

### Threads

- **Публичного API нет.** Сбор через браузер с авторизованной сессией.
- **`serp_type=default` работает, `filter=recent` — нет.** Фильтр «свежие» приносит объявления о продаже машин из Краснодара и Казани.
- **Самое ценное приходит в комментарии под собственным постом.** Поиск их не индексирует. Именно оттуда пришли поправки, новые адреса и жалоба на Сокол.
- **Threads отдаёт только верхний уровень комментариев.** Вложенные ответы через автоматизацию не достать.

### 2ГИС

- Не SSR: `curl` возвращает пустую оболочку, нужен браузер.
- Выдача постранична — первый сбор Алматы взял только первую страницу, из-за чего город был покрыт втрое хуже Астаны.
- Рубрики называются по-разному: «Заправочные станции», «Заправочная станция», «АЗС», «АЗГС».
- Для автоматики показывает капчу.

### Геокодирование

Яндекс Геокодер не знает корпусов и литер. Фолбэки: сначала отбрасывается корпус (`14/1` → `14`), потом литера (`28а` → `28`).

**Главный провал проекта:** Газпромнефть на проспекте Абая 105/1 стояла **в 4,5 км** от реального места — геокодер не нашёл дом и вернул точку «где-то на проспекте» с точностью «улица». Ещё 26 адресов из 230 он выбрасывал молча, и они вовсе не попадали на карту — включая две точки, по которым уже были написаны вердикты.

Лечение: файл `manual.json` с координатами, снятыми прямо с карточек 2ГИС. Сейчас там 11 адресов.

### Сегментация по маркам

Жалобы распределились не по сетям, а по маркам топлива:

- **92** — почти не жалуются
- **95** — больше всего жалоб, марка массовая
- **98** — жалоб меньше, но тяжелее: форсунки, ТНВД, эвакуатор

Эта сегментация проявилась сама. При опросе такой вопрос вряд ли был бы задан.

## Правовая позиция

- Формулировка везде: «водители жалуются», не «плохой бензин».
- Под каждым цветом — цитата с датой, в приложении есть список исходных тредов.
- На первом запуске — экран согласия: сервис информационный, данные из публичных отзывов, лабораторных исследований не проводилось, ответственность за решения на основе карты автор не несёт.
- Владелец АЗС может прислать опровержение — оно попадёт в карточку.
- Слова «исследование» и «доказано» не используются намеренно.

## Технические решения и их причины

**Почему `preferCanvas: true` у Leaflet.** 351 маркер как DOM-элементы тормозили на телефоне. Канвас решил проблему.

**Почему шторка двигается через `transform`, а не `height`.** Анимация высоты заставляет браузер пересчитывать вёрстку каждый кадр — отсюда была дёрганность. `translate3d` уходит на композитор.

**Почему service worker network-first для своих файлов.** Сначала был cache-first, и обновления не доезжали до телефонов. Пользователю пришлось бы чистить кэш руками — вместо этого исправлена причина.

**Почему кэш тайлов увеличен до 2000.** Снижает нагрузку на сервер OSM примерно вдвое: вернувшийся человек не ходит за подложкой в сеть.

**Почему не Carto и не Esri.** Carto теперь требует API-ключ и рисует водяные знаки поверх карты. У Esri нет подписей улиц по Астане и максимальный зум 16 против 19. Вернулись на OSM, включили обязательную атрибуцию.

**Почему вердикты не решает автоматика.** Правило окраски всё ещё меняется — сети перекрашивались несколько раз за две недели. ИИ-агент готовит вердикт, но утверждает человек: пока правило не устоялось, отдавать решение целиком нельзя.

## Известные ограничения

1. **Нет админки и модерации.** Вердикты правятся в JS-файле и деплоятся заново. Проект держится на одном человеке.
2. **Нет защиты от накруток.** Одна громкая жалоба весит столько же, сколько десять тихих. Нет ни порога, ни веса источника.
3. **Кокшетау скрыт.** 19 точек собраны, но в Threads о городе не пишут вообще — карта без единого отзыва бесполезна.
4. **Тайлы на чужом сервере.** Подложка грузится с openstreetmap.org. При заметном росте трафика её могут перекрыть, и карта станет серым фоном с точками. Запасные варианты: платный провайдер (MapTiler, Thunderforest, ~20–25 $/мес) или свой кэширующий прокси на Cloudflare Workers.
5. **Пять точек не встали на карту** — все за городской чертой (капчагайская трасса, трасса на Кокшетау).
6. **Qazaq Oil на Улы Дала.** Двое подтверждают, что заправка существует, 2ГИС по этому адресу её не знает. Не добавлена.
7. **Данные стареют.** Хорошая заправка может испортиться за две недели: NomadOil на Керей в августе ставили в пример, 2 сентября оттуда пришёл тяжёлый случай. Карта узнаёт об этом только когда кто-то напишет.
